# Codex 额度怎么计算：Plus、Pro 限额与查询方法

**直接答案：** Codex 额度不是固定的“每天多少条消息”。OpenAI 会根据 ChatGPT 方案、所用模型、任务规模、上下文、推理强度、工具调用以及本地或云端执行方式计算消耗；本地任务和云端任务还可能共享使用窗口，并可能存在额外的每周限制。最准确的信息来自个人 Usage Dashboard，CLI 用户可输入 `/status` 查看当前状态。

## 为什么不能用固定条数比较

同样发送一条指令，下面两种任务的实际成本不会相同：

- 解释一个 50 行函数，不修改文件；
- 扫描大型仓库、修改多个模块、安装依赖并反复运行测试。

后者需要更多输入上下文、推理、工具执行和输出，因此可能消耗更多用量。OpenAI 官方给出的消息范围是估算，不是每个账号的保证值；模型和产品规则更新后，历史截图也可能失效。

## 影响 Codex 消耗的因素

| 因素 | 常见影响 |
| --- | --- |
| ChatGPT 方案 | 更高方案通常提供更高使用量，但仍有公平使用与产品限制 |
| 模型 | 不同模型的能力、速度和消耗不同 |
| 上下文 | 仓库越大、会话越长，处理的信息通常越多 |
| 任务复杂度 | 跨文件修改、长时间推理和多轮验证通常更耗用量 |
| 工具与检索 | 终端、网络、测试和外部工具会增加工作步骤 |
| 运行位置 | 本地消息和云端任务的估算及限制可能不同 |
| 缓存 | 重复上下文若命中缓存，消耗结构可能不同 |

## 怎么查看剩余额度

### Usage Dashboard

打开 Codex 的 **Settings → Usage**。根据账号当前界面，可查看使用窗口、重置时间、Credits 余额和近期消耗。网上的套餐对比只能用于理解量级，做项目计划时应以自己的 Dashboard 为准。

### Codex CLI

在交互式 CLI 中输入：

```text
/status
```

它会显示当前会话配置及可用的用量信息。开始大型任务前和任务结束后各检查一次，更容易判断自己的实际消耗模式。

## 触及上限后怎么办

1. 查看是短周期窗口还是其他限额，并确认重置时间。
2. 等待窗口重置，避免通过重复重试浪费时间。
3. 在账号允许时切换更节省用量、仍能完成任务的模型。
4. 把大任务拆成边界明确、可验证的小任务，减少无关上下文。
5. 符合条件的 Plus／Pro 用户可按页面提示购买 [Codex Credits](codex-credits.md)。
6. 长期频繁触顶时，再依据实际账单评估更高方案或 API 路径。

OpenAI Support 通常不会为正常用尽的限额手动重置。不要相信“固定条数永久不变”或“所有账号额度完全一致”的承诺。

[Codex Plus、Pro 限额与使用量对比](https://aicz123.com/blog/article-1787668448774/)提供了中文背景说明。**明月Plus是独立第三方服务平台，并非 OpenAI 官方或授权代理。**

## 如何减少无效消耗

- 明确目标、范围、禁止项和完成标准；
- 先让 Codex 定位相关文件，再扩大读取范围；
- 及时结束已经偏离目标的长会话；
- 让项目的 `AGENTS.md` 保持准确、简洁；
- 关闭当前任务不需要的工具和连接；
- 复用测试命令，避免让智能体反复猜测验证方法。

优化用量不等于一味减少提示词，而是减少无关上下文与重复工作。
